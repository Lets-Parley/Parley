WARNING: trustProxyHeaders is false but you are behind an Ingress. Every visitor
will arrive wearing the ingress controller's address, so the room-code throttle
counts the whole internet as one client: eight wrong guesses lock everybody out
of that space.

Set trustProxyHeaders=true — but only if your proxy *overwrites*
X-Forwarded-For. ingress-nginx does by default; with use-forwarded-headers it
appends instead, and then trusting it lets a guesser reset their own limit on
every request.

Check it came up:

    kubectl --namespace {{ .Release.Namespace }} rollout status deploy/{{ include "parley.fullname" . }}
    helm --namespace {{ .Release.Namespace }} test {{ .Release.Name }}

Two things that will bite you later:

  * Upgrades take a few seconds of downtime. Parley's realtime hub is
    in-process, so the chart uses Recreate: the old pod must exit and release
    its boot advisory lock before the new one starts. Clients reconnect on
    their own.

  * Do not roll back onto an image older than the migrations that have already
    run. Parley will refuse to start rather than corrupt the schema. Restore
    the database from backup first, or roll forward.
