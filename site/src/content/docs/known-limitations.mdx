## Scale and availability

<Capability rows={[
  { name: "Multiple replicas", status: "built", detail: "Fanout runs over Postgres <code>LISTEN</code>/<code>NOTIFY</code>, presence and the room-code throttle are rows in Postgres, and simultaneous boots serialize their migrations behind an advisory lock. The socket hub is still per pod, but nothing depends on one pod seeing every socket. Not yet exercised on a real multi-node cluster." },
  { name: "Zero-downtime deploys", status: "built", detail: "The chart rolls with <code>maxSurge: 1</code> / <code>maxUnavailable: 0</code> above one replica. During the rollout old pods serve against the newer schema the new pod migrated to; migrations are additive, so that is fine, and it resolves as the rollout replaces them. At <code>replicaCount: 1</code> there is still a reconnect." },
  { name: "Connection migration during deploy", status: "not-built", detail: "Shutdown closes a pod's WebSockets rather than handing them over; clients reconnect and land on a surviving replica. The reconnect is visible, the state is not lost." },
  { name: "Published performance numbers", status: "not-built", detail: "There is no benchmark, and inventing one would be dishonest. Watch Postgres first — that is where the pressure lands." },
]} />

## Operations

<Capability rows={[
  { name: "Metrics, tracing, request IDs, access log", status: "not-built", detail: "JSON logs to stdout are all Parley emits. Blackbox-probe <code>/readyz</code>, and take request metrics and access logs from your reverse proxy. <code>LOG_LEVEL=debug</code> adds one per-request line naming the socket peer, the <code>X-Forwarded-For</code> chain and the resolved client address — a proxy-diagnosis aid, not an access log: it records no method, path, status or user, and is not retained. See <a href='/operations/observability/'>Observability</a>." },
  { name: "Backups", status: "not-built", detail: "Nothing backs itself up. Schedule <code>pg_dump</code>." },
  { name: "Data retention or cleanup", status: "not-built", detail: "Application records are never deleted automatically. Session authorization expires, but <code>session_tokens</code> rows are not swept; prune them yourself if the instance runs for years." },
  { name: "Down-migrations or rollback", status: "not-built", detail: "Migrations are forward-only and the binary refuses to start against a newer schema. Roll back by restoring a backup taken before the upgrade." },
  { name: "A bind-address setting", status: "not-built", detail: "The process listens on all interfaces; only <code>PORT</code> is configurable. Use a container port binding, a firewall, or a proxy." },

## Access and identity

<Capability rows={[
  { name: "Space roles beyond owner and member", status: "not-built", detail: "The owner role ships and gates membership management — see <a href='/security/authorization/'>Authorization</a> — but there is no admin or read-only role, and any member can still rotate the passcode or open the space. Story mutations and session controls are facilitator-only; ordinary members retain voting, their own standup entries, and their own standup readiness signal." },
  { name: "Per-user or per-team space access", status: "not-built", detail: "A passcode gates a space; identity does not. Gate the whole instance with an SSO proxy if you need this today." },
  { name: "Removing a member", status: "built", detail: "An owner removes a member from the space; their next request sees the stranger view and their sockets for that space are closed. It is not a ban — rotate the passcode too, or they can rejoin with it. The last owner cannot be removed." },
  { name: "Guest links", status: "built", detail: "A facilitator mints a link to one room; whoever opens it takes a seat there and nowhere else, for 24 hours or until it is revoked. The URL is the credential — anyone holding it is the holder. A guest works both room kinds the same way as anybody else: they vote fully in poker, and in a standup take a place in the round and get the turn when it comes round to them. Starting, advancing and skipping the round stay the facilitator's. See <a href='/features/guest-links/'>Guest links</a>." },
  { name: "A guest seat that survives a closed tab", status: "not-built", detail: "A guest-link cookie is scoped to the <em>browsing session</em> — the browser, not the tab. Close the room tab while any other window of that browser is open and the cookie is untouched, so the next person to open the room URL is seated as that guest until the link expires. The cached name and hue live in <code>sessionStorage</code> and do die with the tab, but the room recovers the identity from the cookie. Quitting the browser ends the seat, unless it is set to restore its last session — \"continue where you left off\" restores session cookies along with the tabs. Nothing server-side can tell any of this apart from an ordinary request. Ending the seat on <code>pagehide</code> was considered and rejected: it fires on an ordinary refresh and on mobile backgrounding, so it would strand a guest who did nothing wrong. Use <strong>Leave room</strong>, or revoke the link, when the machine is borrowed or shared." },
  { name: "Account linking when switching to OIDC", status: "not-built", detail: "Anonymous and federated identities are distinct. Existing history remains under the old display records; federated users rejoin spaces with their passcodes." },
  { name: "Sign out everywhere or admin revocation UI", status: "not-built", detail: "Delete rows from <code>session_tokens</code> in SQL. HTTP rejects them immediately; WebSockets start a check every 30 seconds, allow a 30-second timeout, and close with code 1008 on failure. A space owner can remove someone from that space, but that revokes no token and reaches no other space." },
  { name: "Account deletion or data-subject tooling", status: "not-built", detail: "SQL against the documented schema; note that deleting a user who facilitated a session is blocked by a foreign key." },
  { name: "Reading the audit log", status: "not-built", detail: "Org custody actions — a space deleted, an owner granted, an abandoned space claimed, an org purged — are recorded in <code>org_audit_log</code>. Nothing else is, and nothing reads the table: there is no API route and no screen, so reviewing it means querying Postgres. See <a href='/security/organizations/#claiming-an-abandoned-space'>Organizations</a>." },
  { name: "Creating an org", status: "not-built", detail: "The <code>default</code> org is created by the migration; a second one is an <code>insert into orgs</code> in SQL. Membership then follows from the claim value you register on it. See <a href='/operations/organizations/#creating-an-org'>Organizations and claim mapping</a>." },
  { name: "Listing or revoking link guests as an org admin", status: "not-built", detail: "A redeemed signed link mints an identity in no org and no space, so it appears on no members screen and org revocation cannot reach it. Its expiry and the session facilitator's revoke are the controls. This is by design, and the reason an org's member list is not a census of who can reach a room — see <a href='/security/organizations/#the-three-ways-into-a-room'>Organizations</a>." },
]} />

## Security posture

<Capability rows={[
  { name: "SBOM and provenance", status: "built", detail: "Releases produced by the hardened workflow include an image SBOM and a source SBOM, digest-qualified deployment manifests, maximum build provenance, and a GitHub attestation for the final GHCR digest. The SBOMs themselves are unsigned assets; the attestations are the verifiable part. Releases v0.1.0 through v0.2.1 were not backfilled. See <a href='/security/supply-chain/'>Supply chain</a>." },
  { name: "Vulnerability scanning in CI", status: "built", detail: "govulncheck, CodeQL, dependency review, npm audit, and container scanning gate changes." },
  { name: "Automated dependency updates", status: "built", detail: "Dependabot checks Go, web, site, Actions, and Docker dependencies weekly." },
  { name: "HSTS and several modern headers", status: "not-built", detail: "Parley sets CSP, nosniff, X-Frame-Options and Referrer-Policy. Add HSTS, Permissions-Policy and the COOP/COEP/CORP family at your proxy." },
  { name: "General ingress rate limiting", status: "not-built", detail: "Room-code guesses and open identity creation are throttled; spaces, sessions, and stories have configurable caps. General API calls and WebSocket connections still need ingress controls." },
