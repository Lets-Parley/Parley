## Dependencies

Parley has **five direct Go dependencies**:

| Module | What for |
|---|---|
| `github.com/coreos/go-oidc/v3` | OpenID Connect token verification |
| `golang.org/x/oauth2` | Authorization code flow and PKCE |
| `github.com/go-chi/chi/v5` | HTTP routing |
| `github.com/gorilla/websocket` | WebSockets |
| `github.com/jackc/pgx/v5` | Postgres driver and pool |

Six further indirect modules come with those. There is no web framework, no ORM,
no dependency-injection container and no logging library — logging is the
standard library's `log/slog`.

The frontend is React and Vite, built at image-build time and compiled into the
binary. **No frontend dependency is served to a browser at runtime**, and there
is no CDN: the CSP is `default-src 'self'` and everything is same-origin.

## How the image is built

Three stages: Node builds the frontend, Go cross-compiles a static binary with
`CGO_ENABLED=0`, and the result is copied into
`gcr.io/distroless/static-debian12:nonroot`.

That final image has no shell, no package manager and no libc. Its attack
surface is one static binary running as a non-root user. Published for
`linux/amd64` and `linux/arm64` on every `v*` tag.

## What CI actually checks

`go vet`, the full test suite under `-race` against a real Postgres, a frontend
build, and a first-run smoke test that boots the image against an empty database
and asserts it serves a page.

That is a real correctness gate. It is **not** a security gate, and the
difference matters:

## What to do about it

If you are evaluating Parley for somewhere that cares about supply chain, the
honest recommendation is: **build the image yourself from a tagged commit**. The
build is a single Dockerfile with no private steps, it takes minutes, and it puts
the provenance question entirely in your own pipeline where you already have the
signing and attestation you need.

If you use the published image, pin the digest and scan it. Do not rely on
`latest`.

## Known vulnerable versions

**v0.1.0** contains a room-code throttle bypass, fixed in v0.2.0. The tag and
image were left in place rather than retagged, so that anyone who pulled that
digest still receives what they pulled. Do not deploy it.

There is no separate security advisory for it: the repository had no known
installs at the time, and the release notes carry the warning. Report anything
new through a
[security advisory](https://github.com/lets-parley/parley/security/advisories/new).
