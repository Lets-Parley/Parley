## Most tools want an account. Parley wants a link.

```sh
git clone https://github.com/lets-parley/parley && cd parley
cp .env.example .env        # set POSTGRES_PASSWORD to anything
docker compose up -d
```

That is the whole install, and it is on `:8080`. The frontend is compiled into
the binary, so there is no second service, no Node runtime in production, and no
way for the two halves to end up at different versions.

## What Parley doesn't do

Parley runs as a **single replica**, has **no metrics endpoint**, **no roles
beyond member and facilitator**, and **no audit log**. Room codes are stored
readable on purpose, so a database dump discloses them.

Those are on one page, with the workaround next to each, because you should find
out now and not three weeks in.

[Known limitations →](/known-limitations/)

## It behaves itself in production

- `/healthz` never touches the database, so a Postgres blip does not restart the
  container and drop every socket in the room
- Migrations run at boot, in a transaction each, and the binary refuses to start
  against a schema newer than it knows
- Structured JSON logs to stdout, and a boot line that tells you exactly what
  configuration resolved to
- `distroless/static`, non-root, no shell, `CGO_ENABLED=0`, amd64 and arm64
- CSV exports escape spreadsheet formulas, and never contain a vote you were not
  allowed to see
- One advisory lock means one replica — enforced at boot rather than discovered
  at runtime
