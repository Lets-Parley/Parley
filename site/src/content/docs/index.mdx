## Most tools want an account. Parley wants a link.

Same link for planning poker and standup. Two commands and a `.env` file, no
platform team required:

<Tabs>
  <TabItem label="Compose">
    ```sh
    git clone https://github.com/lets-parley/parley && cd parley
    cp .env.example .env        # set POSTGRES_PASSWORD to anything
    docker compose up -d
    ```
    That is the whole install, and it is on `:8080`. Compose binds to localhost
    until you say otherwise.
  </TabItem>
  <TabItem label="Prebuilt image">
    ```sh
    docker run -d --name parley -p 8080:8080 \
      -e DATABASE_URL='postgres://parley:secret@db:5432/parley' \
      -e BASE_URL='https://parley.example.com' \
      ghcr.io/lets-parley/parley:latest
    ```
    Multi-arch, amd64 and arm64. Bring your own Postgres.
  </TabItem>
  <TabItem label="Kubernetes">
    Manifests live in `deploy/k8s/` — a Deployment pinned to one replica, a
    Service, and a commented Ingress carrying the read-timeout annotations
    WebSockets need. [Deploying to Kubernetes →](/operations/kubernetes/)
  </TabItem>
</Tabs>

The frontend ships inside the binary, so there is no second service, no Node
runtime in production, and no way for the two halves to end up at different
versions. Migrations run themselves at boot.

## What's in it

<CardGrid>
  <Card title="Planning poker">
    A story queue with real ticket references. Four decks — Fibonacci, modified
    Fibonacci, T-shirt, powers of two — each carrying `?` and a coffee card.
    Votes stay hidden until the round opens, and a T-shirt round reports mode
    and range rather than an average nobody can act on.
    [What it does →](/features/planning-poker/)
  </Card>
  <Card title="Daily standup">
    Round-robin with a 90-second clock, so the quiet people get their turn.
    Skip someone without losing their place. Whatever you wrote under "today" is
    waiting under "yesterday" tomorrow, and blockers collect into a list you can
    paste into a channel. [What it does →](/features/daily-standup/)
  </Card>
  <Card title="Spaces">
    One memorable link per team, `/s/platform-team`, and a six-character room
    code that throttles wrong guesses per address. The roster shows who is here
    and which table they are sitting at.
    [What it does →](/features/spaces-and-room-codes/)
  </Card>
</CardGrid>

## What Parley doesn't do

- **One replica, and it enforces that.** A second instance refuses to start
  rather than serve a divergent board. Size it vertically; deploy when nobody
  is mid-session.
- **No roles beyond member and facilitator.** Any member can rotate the room
  code or open the space. Keep membership deliberate, or put an SSO proxy in
  front of it.
- **No metrics, tracing, SBOM or image signing.** Structured JSON logs to
  stdout are all it emits; build from a tagged commit yourself if you need
  provenance.
- **Turning on OIDC signs everyone out.** Anonymous accounts are not linked to
  federated ones. Switch on an instance whose history you are willing to leave
  behind.

All of them are on one page, each with its workaround, because the gaps
are the reason to believe the rest.

[Known limitations →](/known-limitations/)

## In production

- A Postgres blip does not restart the container and drop every socket in the
  room — the health check never touches the database
- The container is distroless and non-root, no shell, one static binary —
  amd64 and arm64
- CSV exports cannot run formulas in your spreadsheet, and never contain a vote
  you were not allowed to see
