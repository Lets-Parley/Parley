Three supported shapes: Compose, [Kubernetes](/operations/kubernetes/), or the
binary on its own. All three are the same process with the same configuration —
see the [configuration reference](/reference/configuration/) for every variable.

For a first run, start at the [Quickstart](/quickstart/).

## Docker Compose

The shipped `docker-compose.yml` runs Parley plus a Postgres 16, with a named
volume for the data.

Three of its defaults are deliberate and worth knowing before you change them:

- **The password has no default.** `POSTGRES_PASSWORD` is written
  `${POSTGRES_PASSWORD:?...}`, so Compose refuses to start without one rather
  than shipping a guessable default into production. Self-hosters paste compose
  files verbatim; this one will not let you paste a weak secret you did not
  choose.
- **The port is bound to loopback**, `127.0.0.1:8080:8080`. Nothing is exposed to
  your network until you decide to expose it. Prefer putting a
  [reverse proxy](/operations/reverse-proxy/) in front over changing this to
  `0.0.0.0`.
- **`TRUST_PROXY_HEADERS` defaults to false**, which is correct for the default
  loopback binding and wrong the moment you put a proxy in front. See below.
- **Postgres is pinned to a major version.** An unpinned `postgres:` tag that
  crosses a major release leaves the data directory unreadable. See
  [Upgrading](/operations/upgrading/).

## The image

`ghcr.io/lets-parley/parley`, multi-arch for `linux/amd64` and `linux/arm64`,
published from exact semantic-version GitHub Releases and anonymously pullable.

It is built in three stages and the final one is
`gcr.io/distroless/static-debian12:nonroot` — no shell, no package manager, no
libc to patch, running as a non-root user. The Go binary is static
(`CGO_ENABLED=0`).

The image declares its own `HEALTHCHECK`, which runs `parley -healthcheck`
against `/readyz` over loopback every 15 seconds.

Pin a version rather than tracking `latest` if you want reproducible deploys.
Each GitHub Release includes digest-qualified Compose and Kubernetes manifests,
an SPDX SBOM, and verifiable provenance for the published digest; see
[Supply chain](/security/supply-chain/).

## The bare binary

`go build ./cmd/parley` produces a single file with the frontend inside it. Give
it a `DATABASE_URL` and it runs.

:::caution[There is no bind-address setting]
`PORT` sets the port; the process always listens on **all interfaces**. If you
run the bare binary on a multi-homed host and want it reachable only on
loopback, you need a firewall rule or a proxy — Parley cannot be told to bind
`127.0.0.1`.
:::

## Getting TRUST_PROXY_HEADERS right

This setting is wrong in both directions and both failures are real.

- **Directly reachable, set to `true`** — a caller sets their own
  `X-Forwarded-For`, so the room-code throttle keys on an address they control
  and never fires. Codes become brute-forceable.
- **Behind a proxy, set to `false`** — every request appears to come from the
  proxy, so the whole internet shares one throttle bucket. Eight wrong guesses
  by anyone locks everyone out of that space.

Set it to `true` if and only if a proxy you control sets `X-Forwarded-For`
itself. The Kubernetes manifest sets it; Compose deliberately does not.
