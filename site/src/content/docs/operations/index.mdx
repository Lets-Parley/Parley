Parley is one Go binary with the frontend compiled into it, plus a Postgres
database. There is no second service, no Node runtime in production, no cache to
warm and no queue to drain.

That buys a very small operational surface. Parley runs happily on one replica
or several — fanout, presence and the room-code throttle all go through
Postgres — so the shape of the deployment is your call. If you read one page
here before deploying, read
[Scaling and limits](/operations/scaling-and-limits/).
